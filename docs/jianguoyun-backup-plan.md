# Aegis 3.4.3 项目分析与坚果云备份开发方案

分析日期：2026-10-08。依据为本地源码、实际 Gradle 配置检查和坚果云官方文档。

当前状态：调研、方案、实现与验证均已完成。功能范围为“自动上传加密备份，可从坚果云手动恢复”。

阶段任务、验收条件与进度见 [分阶段开发计划](./jianguoyun-development-plan.md)，实际验证结果见 [验证记录](./jianguoyun-validation.md)。

## 1. 项目现状

这是 Android 双因素认证应用 Aegis Authenticator，版本为 3.4.3，包含一个 `app` 模块，界面采用 Java、Android XML 和 Material 组件。不是网页项目，也没有需要部署的服务端。

| 项目 | 已核实的情况 |
| --- | --- |
| 开发语言 | Java，源码兼容级别为 Java 17 |
| Android 支持 | minSdk 23，compileSdk 和 targetSdk 均为 36 |
| 构建 | Android Gradle Plugin 8.10.0，Gradle Wrapper 8.14.5 |
| 依赖注入 | Dagger Hilt |
| 本地持久化 | 认证条目存放在仓库 JSON；Room 用于审计日志 |
| 加密 | AES-256-GCM，密码派生使用 scrypt，指纹解锁使用 Android Keystore |
| 现有备份 | Android Storage Access Framework 文件备份，以及 Android 系统备份 |
| 网络能力 | 主 Manifest 未声明 INTERNET；项目未声明 OkHttp、Retrofit 或 WorkManager 依赖 |
| 测试基础 | JUnit、Robolectric、Espresso；已有导出、独立备份密码、仓库与导入测试 |
| 项目许可 | GPL v3，见根目录 LICENSE |

主要代码位于 `app/src/main/java/com/beemdevelopment/aegis/`，下面的路径均相对于此目录，资源和构建文件另行标明。

## 2. 可以复用的代码与调用链

### 2.1 保存和自动备份入口

新增、编辑、删除、分组、图标调整和导入等操作通过 Activity/Fragment 的 `saveAndBackupVault()`，最终进入 `vault/VaultManager.java:139` 的 `saveAndBackup()`。

该方法先保存仓库，再根据设置触发本地文件备份和 Android 系统备份。这是接入坚果云自动备份的主要入口，云端调度失败应记录为备份失败，不能使已经成功的本地保存被报告为失败。

不是所有写入都经过该方法：初始化、首次导入和关闭加密分别存在独立路径。因此接入时还要检查新设备恢复、关闭加密和紧急清除，而不是只添加一个上传按钮。

### 2.2 加密备份格式

`vault/VaultRepository.java:140` 的 `export()` 已能生成标准 Aegis 加密备份；`vault/VaultFile.java:124` 的 `exportable()` 则能直接转换已经落盘的加密文件。

更适合后台复用的先例在 `AegisBackupAgent.java:73`：

```java
VaultFile vaultFile = VaultRepository.readVaultFile(this);
byte[] bytes = vaultFile.exportable().toBytes();
```

这条路径保留仓库密文，无需取得内存中的主密钥，也无需解锁仓库。`vault/slots/SlotList.java:81` 的 `exportable()` 会去掉仅本机可用的指纹槽；如果设置了独立备份密码，还会去掉普通仓库密码槽。

坚果云备份应复用上述转换，并在入口和后台执行时检查文件确实加密、存在可用于恢复的密码槽。直接上传内部 `aegis.json` 会跳过这些导出规则。

上传文件继续使用标准 Aegis JSON，账号、图标、分组等内容由现有仓库格式承载。无需修改 OTP 算法或增加一套云端加密格式。

### 2.3 现有备份执行器的边界

`vault/VaultBackupManager.java:57` 使用单线程 ExecutorService，把缓存文件复制到 SAF URI，成功或失败后删除临时文件。它还负责本地文件版本保留。

可借鉴它的串行处理和版本保留规则，但网络上传需要进程退出后的重试和凭据管理，不能把 HTTP 请求直接塞进这条本地复制流程。现有执行器本身也不是持久任务队列。

### 2.4 手动恢复

已有仓库的恢复链路是：临时文件 → `importers/AegisImporter.java` → 输入备份密码 → `ui/ImportEntriesActivity.java` → 选择条目、重复检测或显式清空后导入 → 保存仓库。

新安装的恢复链路位于 `ui/slides/WelcomeSlide.java:57` 和 `ui/IntroActivity.java`。它先解密验证备份，再写入仓库并完成初始化。应让云端下载入口也能服务这条路径，避免用户必须先新建空仓库才能恢复。

现有导入不是自动合并更新协议。第一版恢复复用现有交互，由用户确认导入范围；已有仓库默认保留现有条目，清空后恢复沿用现有确认流程。

## 3. 坚果云接入方式

采用坚果云 WebDAV。官方文档确认服务器地址为 `https://dav.jianguoyun.com/dav/`，连接需要坚果云账号和第三方应用密码。应用密码与备份解密密码用途不同：前者访问云盘，后者解密 Aegis 文件。[官方服务器配置](https://help.jianguoyun.com/?p=3234)、[官方应用授权说明](https://help.jianguoyun.com/?p=2064)。

官方目前公开的限制包括免费账号每 30 分钟 600 次请求、付费账号 1500 次请求，以及单次目录请求最多返回 750 个文件或文件夹。第一版使用有限版本保留、合并连续保存产生的待上传请求，并在超出目录读取能力时明确报告，不能把不完整列表用于删除历史备份。[官方限制](https://help.jianguoyun.com/?p=2064)。

新增一个轻量 WebDAV 客户端，使用 `PROPFIND` 列目录、`MKCOL` 创建专用目录、`PUT` 上传、`GET` 下载和 `DELETE` 清理本应用历史版本。建议使用 OkHttp 实现 HTTP 传输，具体依赖版本在实现时根据 SDK 和构建兼容性锁定。

后台上传采用 AndroidX WorkManager，利用网络约束、持久调度和退避重试；实际执行时间受 Android 后台调度影响。[Android 官方说明](https://developer.android.com/develop/background-work/background-tasks/persistent)。

本次未提供云盘凭据，也没有对真实账号执行操作；上述请求在坚果云上的具体响应仍需实现后的真实环境联调。

## 4. 第一版的具体行为

### 4.1 设置与备份

在“备份”中增加“坚果云备份”入口，配置账号、应用密码和远程目录，提供测试连接、自动备份开关、立即备份、历史备份列表和手动恢复。

服务器固定为坚果云 HTTPS 地址，第一版不增加通用 WebDAV 服务器配置。远程目录可以修改，但要逐段编码和校验，不能接受上级目录跳转、完整外部 URL 或带凭据的地址。

只有加密仓库可以开启云端备份。开启后先创建一次备份，后续在保存成功后调度上传；连续保存可合并尚未开始上传的快照，已经开始上传的快照保持不可变。

备份文件放在专用目录下，并按随机生成的安装标识划分设备目录，避免多设备覆盖相同文件。文件名使用时间和随机标识，默认每个设备保留最近 5 份，可配置有限保留数量。恢复列表可以浏览其他设备的备份；自动清理只处理当前设备目录中严格匹配本应用规则的文件。

离线或暂时性服务器错误保留待上传快照，网络恢复后重试。上传重试复用相同快照和远程文件名；新版本上传并验证完成后，再清理超出数量的旧版本。

上传采用独立文件名的 PUT，成功后通过 GET 比较内容摘要，再记录为成功。未确认成功前不删除旧备份；发生网络中断时，对同一文件的重试应保持幂等。失败残留文件只能在严格限定的本应用目录内处理，恢复时仍要解密验证。

状态区分未配置、等待网络、等待上传、上传中、成功和失败。任务入队不显示“备份成功”；上传失败和历史版本清理失败分别显示，便于判断数据是否已经备份。

### 4.2 手动恢复

用户选择云端版本 → 有界下载到私有临时文件 → 检查 Aegis 格式和加密状态 → 输入该版本对应的备份密码 → 解密验证 → 进入现有恢复流程。

格式损坏、密码错误或用户取消均不能改动现有仓库。下载只接受限定服务器和目录下的文件；响应内容、文件大小和 XML 解析均设置边界，禁止 XML 外部实体。

应用密码不会写入仓库备份。新设备需要重新配置坚果云凭据，再使用备份密码恢复；也可以继续使用现有文件导入入口。

## 5. 从现有代码发现的关键约束

| 约束与证据 | 实现要求 |
| --- | --- |
| 应用启动清空缓存，`AegisApplicationBase.java:57` | 重试快照放到 `noBackupFilesDir` 专用目录；恢复临时文件按完成或取消清理 |
| `VaultManager.lock()` 会把内存仓库设为 null | Worker 只读取持久快照，不能依赖后台 `getVault()` |
| `KeyStoreHandle.java:51` 的现有密钥要求用户认证 | 为云盘凭据使用独立别名和允许后台读取的 Keystore 密钥；复用 CryptoUtils 的 AES-GCM 处理 |
| `KeyStoreHandle.clear()` 删除所有别名；关闭加密会调用它 | 关闭加密时取消云端任务、清理本地快照及凭据，使设置与密钥状态一致 |
| 两份系统备份规则都包含所有 SharedPreferences | 云盘凭据加密后存放在不参与系统备份的私有文件；不能放进默认偏好或任务 InputData |
| 紧急清除目前只删除主仓库，见 `PanicResponderActivity.java:40` | 同时取消任务和正在执行的网络请求，清理本地快照及凭据；检查已失效的任务不能继续上传 |
| 仓库用 AtomicFile 保存，但读写方法没有统一的并发锁 | 快照读取必须与仓库写入、删除协调；不把 AtomicFile 当成并发控制机制 |
| 现有 BackupResult 和错误对话框只区分本地、Android 两类备份 | 云端状态独立记录，并纳入备份提醒判断；不能误显示成 Android 备份 |

紧急清除取消的是本机后续工作，已经存放到云盘的历史备份继续存在；第一版不在该动作中自动删除远程历史文件。已发送到服务器的请求也不能承诺能够撤回。

关键错误应分类处理：401/403 提示检查授权且停止自动反复尝试；网络错误、限流和可恢复的服务器错误按退避策略重试；目录错误、配额不足、内容损坏和密钥失效显示明确原因。重试有上限，账号或目录变更后旧任务不得使用新账号上传旧队列。日志和错误信息不包含应用密码、Authorization 或仓库内容。

## 6. 拟修改范围与执行顺序

新增代码集中在 `backup/` 包，包含 WebDAV 客户端、凭据存储、备份状态、快照与调度管理、Worker；新增一个坚果云设置与恢复界面，复用现有 Material 样式和安全对话框。类名在实现时以仓库命名习惯为准。

| 现有位置 | 计划修改 |
| --- | --- |
| `app/build.gradle` | 增加网络和后台任务依赖；给无 Git 元数据的源码包增加构建元信息回退值 |
| `app/src/main/AndroidManifest.xml` | 增加 INTERNET、ACCESS_NETWORK_STATE 和新界面声明 |
| `vault/VaultManager.java` | 保存后调度云端备份；关闭加密时停止云端工作 |
| `vault/VaultRepository.java` | 必要时为磁盘读写与快照增加统一并发保护，保持现有调用签名 |
| `Preferences.java` 和 `ui/MainActivity.java` | 云端成功时间和失败状态纳入提醒，保留原有两类备份的行为 |
| `ui/fragments/preferences/BackupsPreferencesFragment.java` | 添加坚果云入口及状态摘要 |
| `ui/slides/WelcomeSlide.java` | 接入首次安装时的云端恢复入口，复用已验证的导入逻辑 |
| `AegisApplicationBase.java` | 启动后协调持久队列与 WorkManager，处理未完成工作和孤立快照 |
| `ui/PanicResponderActivity.java` | 取消云端任务并清理本地新增持久数据 |
| 资源、FAQ 和测试 | 添加中英文文案、界面资源、使用说明与针对新行为的测试 |

执行顺序：

1. 修复源码包构建阻塞，完成基线编译及相关测试。
2. 实现凭据存储、WebDAV 请求和连接测试。
3. 实现标准加密快照、持久上传、任务合并、状态和版本保留。
4. 接入设置、已有仓库恢复和首次安装恢复，补齐关闭加密与紧急清除链路。
5. 运行单元测试、相关设备测试、Lint 和 Debug 构建，再进行真实坚果云联调。

第一版的开发结果应包括源代码、可构建的 Debug APK、使用说明和验证记录。不能用模拟服务测试的结果替代真实云盘兼容性验证。

## 7. 本地构建检查与验收

本机已安装 JDK 21 和 Android SDK 36。当前目录没有 `.git`。先执行离线 Gradle 检查时，插件未命中缓存；随后联网执行 `gradlew.bat help --console=plain`，已经进入 `:app` 配置阶段，但退出并报告：

```text
app/build.gradle line: 8
Process 'command 'git'' finished with non-zero exit value 128
fatal: not a git repository (or any of the parent directories): .git
```

根因是 `app/build.gradle:15-16` 强制读取 Git 提交号和分支。建议只给无 Git 元数据的源码包提供回退字符串；有 Git 元数据时保留实际信息。修复后仍需继续验证依赖解析、编译和测试。目前没有成功构建 APK，也没有运行应用测试。

需要覆盖的验收场景：

- 新增、编辑、删除和导入后，云端产生可恢复的标准加密备份；普通密码与独立备份密码均符合原有导出规则。
- 仓库锁定、应用进程结束或设备重启后，待上传内容可恢复执行；任务入队和任务执行期间再次保存不会丢失最后一次修改。
- 离线、超时、认证失效、限流、目录不存在和配额不足有明确状态；云端失败不影响本地保存。
- 重试使用相同内容和文件名，连续保存不会造成失控的上传积压；只在确认新版本成功后清理旧版本。
- 超出目录读取能力时不进行不完整的版本清理；其他设备和无关文件不被删除。
- 已有仓库和新安装均能手动恢复；损坏文件、错误密码、取消和超限下载不会改动本地数据。
- 关闭自动备份、退出云盘账号、关闭仓库加密、修改账号或目录、紧急清除均正确处理待上传及执行中的任务。
- 本地 SAF 备份、Android 系统备份、导出和指纹解锁回归通过；凭据不会出现在日志、系统备份或任务数据库中。

联网联调需要在应用界面配置坚果云账号和应用密码。应用密码只保存在应用的加密存储中，不要提交到版本库，也不要在 issue、日志或截图中粘贴。
